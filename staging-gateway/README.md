## Зачем нужен шлюз

Android-приложение использует PHP API для подписи запросов к Cloudflare Worker. Секрет HMAC нельзя передавать на телефон, поэтому **отдельный тестовый сервер** подписывает обращения к `uber-v3-staging`. Production API и его секреты не затрагиваем.

## Размещение на Timeweb (виртуальный хостинг)

На Timeweb для отдельного сайта `ts52_staging` уже настроен HTTPS и `public_html`.
Код для этого поддомена нужно **разложить по каталогам**, а не копировать весь репозиторий в `public_html`:

```text
ts52_staging/
├── _bootstrap.php                     <-- staging-gateway/_bootstrap.php
├── private/                           <-- только на сервере, НЕ в Git
│   ├── staging-hmac.key                <-- отдельный staging Worker HMAC
│   ├── staging-access.key              <-- независимый тестовый токен
│   └── staging-rate-limit.json         <-- создаёт PHP после обновления
└── public_html/                       <-- DOCUMENT_ROOT staging сайта
    └── api/
        ├── calculate.php               <-- staging-gateway/public/api/calculate.php
        ├── order.php                   <-- staging-gateway/public/api/order.php
        └── order-status.php            <-- staging-gateway/public/api/order-status.php
```

**Никогда не копировать `private/`, `_bootstrap.php`, `tests/` или README внутрь `public_html`.**
`_bootstrap.php` должен лежать рядом с `public_html`: публичные API подключают его через
`dirname(__DIR__, 2) . '/_bootstrap.php'`.
Не публиковать этот код на основном сайте `transfer-servis52.ru`.

## Изолированные секреты

По умолчанию шлюз читает **два текстовых файла** в `ts52_staging/private/`.
Переменные окружения **не обязательны на Timeweb**:

- `staging-hmac.key` — значение **только staging** Worker `PROXY_HMAC_SECRET`;
- `staging-access.key` — другой случайный тестовый токен (минимум 32 символа),
  передаваемый в запросе `X-Staging-Access-Token`.

Для окружений с управлением PHP-FPM можно явно задать `TS_STAGING_HMAC_SECRET_FILE`
и `TS_STAGING_TESTER_TOKEN_FILE`: значения — **абсолютные пути** к секретным файлам вне
DOCUMENT_ROOT, они имеют приоритет перед путями Timeweb. Если файл отсутствует, пуст,
не читается, слишком короткий или находится внутри публичного каталога — API возвращает
`503 staging unavailable` без раскрытия деталей.

Секреты не добавлять в репозиторий, APK, сообщения чата, скриншоты или логи.
Для `staging-hmac.key` использовать **то же значение**, что у staging Worker
`PROXY_HMAC_SECRET`, но **никогда не копировать ключ production**.
Если staging HMAC утрачен, ротировать только staging Worker и соответствующий файл.
Права доступа к файлам ограничить владельцем сайта/PHP; убедиться, что PHP может их читать.

Сеть: обеспечить ACL/IP-ограничение или эквивалентную защиту и действующий HTTPS.
Хост `staging.transfer-servis52.ru` работает по схеме Cloudflare DNS only, поэтому WAF-правила Cloudflare для проксируемого сайта здесь не применяются автоматически. ACL и сетевые лимиты хостинга требуют отдельной проверки.

### Прикладные лимиты запросов в черновой версии

После принятия `X-Staging-Access-Token` шлюз ограничивает число запросов в 60-секундном окне (общий бюджет для всех тестировщиков одного PHP-хоста):

- `/calculate`: 30 запросов/60 секунд;
- `/orders`: 10 запросов/60 секунд;
- `/order-status`: 120 запросов/60 секунд.

При превышении возвращает HTTP 429, `Retry-After: 60`, `{"ok":false,"error":"rate limited"}`. Счётчики с блокировкой `flock` записываются в `private/staging-rate-limit.json`, без токенов или персональных данных. **PHP-процесс должен иметь право создавать и изменять этот файл**; при отсутствии прав или повреждении состояния шлюз возвращает 503 и не пересылает запрос на Worker. Это прикладной лимит для *авторизованных* запросов, не замена IP ACL и защите nginx от неавторизованного трафика.

**Перед обновлением Timeweb:** убедиться, что PHP может записывать в `ts52_staging/private/`. Затем загрузить только новую версию `_bootstrap.php` в существующий staging-каталог; `private/*.key` не менять. Повторно проверить авторизованный `/calculate` и защитный отказ без токена. Если PHP не имеет прав на создание счётчика — 503: сначала исправить права доступа, а не выключать проверку. Ротацию Debug-токена выполнять отдельно после приёмки.
Токен Debug APK временный: не распространять APK; после завершения staging-испытаний отзывать и заменять его при необходимости.

### Нерешённое замечание: сетевой IP-ACL (28.10.2026)

Владелец сообщил, что настройку IP allowlist в панели Timeweb не нашёл, а `ts52_staging/public_html/.htaccess` отсутствует. Это не отменяет подтверждённой защиты секретов за пределами DOCUMENT_ROOT, проверки `X-Staging-Access-Token` и прикладного rate limiting; однако **сетевой IP-ACL на уровне хостинга не подтверждён**. Не создавать широкую блокировку без стабильного исходящего IP тестировщика и проверенного отката, иначе Android Debug может перестать обращаться к PHP API. Согласно документации Timeweb, `.htaccess` применяется Apache к динамике, а не к статическим файлам, отдаваемым Nginx; для текущих PHP API это подходящий механизм при согласованном allowlist. Ограничение остаётся открытым пунктом приёмки, а не успешно пройденной проверкой.

**Решение владельца (28.10.2026):** настройку IP allowlist и `.htaccess` пока не выполнять. Сетевое ограничение остаётся **отложенным, не внедрённым**; действующая защита PHP API по токену и rate limiting сохраняется. Не выдавать отсутствие ACL за успешно пройденную проверку и не создавать конфигурацию без отдельного решения.
