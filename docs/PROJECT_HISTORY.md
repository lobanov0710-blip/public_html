### AUDIT-01 — начало сверки релиза

База проверки: [public_html/main, a32ca8f](https://github.com/lobanov0710-blip/public_html/commit/a32ca8f94c70dddf2c1cdb94b047440f2e31d4d1). Рабочая ветка: `audit/20261125-release-verification`. На 25.11.2026 дерево main проверено, предыдущий журнал изучен. Старая ветка audit/homepage-v2 не используется для новых изменений.

В ходе предшествующего аудита прочитаны публичные главная, nn-moscow.html, robots.txt и sitemap.xml (11 URL). Last-Modified главной — 12.11.2026. Это не доказывает побайтовое совпадение релиза с main. Журнал от 12.11.2026 также не подтверждает публикацию указанного коммита.

Предлагаемый состав production-релиза для проверки: отслеживаемые в базовом коммите публичные корневые HTML, CSS, robots.txt, sitemap.xml, rss.xml, .htaccess, файл подтверждения Яндекс, каталоги images/, js/ и четыре production PHP-файла api/. Не включать .git/, .github/, docs/, tests/, staging-gateway/, .editorconfig, резервные копии, временные файлы и секреты. Отдельно проверить необходимые файлы хостинга (например, .well-known/), не удалять их автоматически. HMAC хранится вне DOCUMENT_ROOT; его содержимое не читать и не передавать.

Критерии закрытия: подтверждён фактический DOCUMENT_ROOT production; получен перечень опубликованных файлов, включая скрытые; сверены пути и Git blob SHA либо SHA-256 с согласованным релизом; все расхождения классифицированы; исключение служебных файлов подтверждено или согласовано исправление; результат записан в журнал. Если есть расхождения, публикацию исправлений и повторную проверку выполнять отдельно после согласования. Архив или манифест должен быть получен из фактического DOCUMENT_ROOT, а не из локального репозитория.

На данный момент файловая система Timeweb не проверена; полного манифеста или снимка production нет. AUDIT-01 не закрыт. Реальные расчёты, заявки, Telegram/FCM, запись в D1, изменение production и STAGING не выполнялись.
